## 1. llama.cpp `ggml-hexagon` 2.0 merged

- **Summary:** Qualcomm's Max Krasnyansky merged [PR 32582](https://github.com/ggml-org/llama.cpp/pull/32582), "ggml-hexagon 2.0: support for int-hmx, automatic f32 → f16 lowering, and generic dma pipelines", at 3:00pm on 26 Nov 2026. It is included in nightlies such as [b12774](https://github.com/ggml-org/llama.cpp/releases/tag/b12774).
- **VERIFIED FACT:** merged (time re-read from the GitHub API on 28 Nov 2026). The change is about 36.7k lines (author's figure; line count not re-counted).
- **Content (as described by the pull request):** an integer matrix-unit mode (`w8a8`, dynamically quantised), automatic f32-to-f16 conversion across the graph, mixed f32/f16 support in every Hexagon op, and direct-memory-access pipelines throughout.
- **CLAIM (author, not reproduced):** on a Galaxy S26+ (Hexagon v81), prompt processing 34–62% faster and token generation 9–27% faster (for example Gemma-4-E2B Q4_0 from 37.4 to 41.2 tokens/s); up to 67% faster prompt processing on v85; and a small generation dip (−2.6% on Qwen3.5-4B) on older v75 hardware, with the author noting the kernels still need tuning.
- **Reproduced:** no.
- **Why it matters for FR3K:** the REDMAGIC 11S Pro has a Hexagon v81 NPU, so this is the most relevant NPU change so far for running GGUF models without QNN conversion.
- **Next action:** [EXP-2026-008](../experiments/EXP-2026-008-ggml-hexagon-2-ab-v81.md), an A/B `llama-bench` before and after this commit. It is blocked until the Hexagon SDK is available (see EXP-2026-001).

## Also noted: HexAnima (outside this window)

- **Summary:** [ayanoby/hexanima](https://github.com/ayanoby/hexanima), an offline, no-root anime image generator for Android on Snapdragon NPUs with custom matrix-unit kernels. Created 5 Nov 2026.
- **CLAIM (README, not reproduced):** about 7 seconds per 512×768 image on a Snapdragon 8 Gen 1 (as reported on Friday); the README also describes much slower figures (about 40 seconds for 512×768) for its optional larger models.
- **VERIFIED FACT (correction to the Friday digest, read on 28 Nov 2026):** the repository's own `LICENSE` file is MIT. The README states "non-commercial use only" for several optional model packs (for example the Qwen Research License and FLUX Kommunity License packs), and `THIRD_PARTY.md` lists each model's separate terms. So the code is MIT but the **model weights carry mixed and often non-commercial terms**. Treat any commercial use as blocked until each weight licence is checked.
- **Why it did not make the top three:** outside the window, and the weight licences limit its use. It may merit a separate look for FR3K AFTER DARK.
